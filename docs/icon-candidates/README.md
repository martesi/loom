# Loom icon candidates

Three single-app-icon concepts are provided for review. Each uses a rounded-square frame, following the macOS app-icon convention. `current-mark.svg` is an unchanged reference copy of `frontend/public/loom-mark.svg`; it remains the current mark and is not being replaced.

**No candidate has been selected. Wiring a candidate into the build is out of scope for this change. The current mark stays the app icon until the user chooses a candidate.**

- **Current mark** — two offset rings suggest linked images and a loom shuttle.
- **Warp and shuttle** — contrasting shuttle crosses four visible warp threads. This direction **fails reliable loom recognition at 16–32 px**: the threads merge and it can read as a bar across fence bars. It is shown for comparison, not claimed to meet the small-size recognition criterion.
- **Frame and shuttle** — a simplified loom frame and vertical warp threads with a contrasting shuttle. Review as a secondary option; at 16 px the frame may read as a generic woven/grid mark rather than unmistakably as a loom.

Rendered review PNGs are generated by running `bun scripts/render-icon-candidates.ts` from `frontend/`. They are written to the git-ignored `.cache/icon-candidates/` directory and are not committed. `legibility-sheet.png` shows each candidate at native size and as nearest-neighbor enlargements (16 px at 4× and 32 px at 2×), so the pixel grid is visible. The frame-and-shuttle candidate is intentionally retained as a weaker option pending review. The macOS layer composition proof is `macos-layer-check.png`; the 1024 px source render is also saved separately as `macos-layer-1024.png`.

The macOS layer uses the Loom SVG at scale 1.0, with no automatic fill, recoloring specialization, shadow, or translucency. Its blue rounded-square artwork reaches the canvas edges; the existing 12/56 corner radius (about 21.4% of the side) is close to the macOS app-icon corner shape. Full-size placement avoids an inset tile; the system mask supplies the final outer silhouette. Linux verification cannot establish the generated `Assets.car` or packaged macOS icon, so those remain unverified.
